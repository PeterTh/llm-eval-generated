================================================================================
BLACK-SCHOLES HYBRID PARALLELIZATION IMPLEMENTATION
================================================================================

PROJECT OBJECTIVE:
Parallelize the black-scholes benchmark code using a hybrid approach combining
MPI, OpenMP, and CUDA for maximum parallel performance on an accelerator cluster.

================================================================================
IMPLEMENTATION SUMMARY
================================================================================

HYBRID PARALLELIZATION APPROACH:

1. MPI (Message Passing Interface) - Process-Level Distribution
   - Distributes option pricing across multiple MPI processes/nodes
   - Each MPI rank processes a contiguous subset of options
   - Work distribution formula: optionsPerRank = (numOptions + size - 1) / size
   - Results gathered using MPI_Gatherv with proper displacements
   - Deterministic: all ranks generate identical option set, process subset

2. OpenMP (Shared Memory) - Thread-Level Parallelism
   - Parallelizes computation loop within each MPI process
   - Uses dynamic scheduling: #pragma omp parallel for schedule(dynamic)
   - Enables multi-threaded execution on multi-core systems
   - Implicit reduction through separate result arrays

3. CUDA (GPU Acceleration) - GPU-Level Parallelism
   - Implemented Black-Scholes kernel for GPU execution
   - Kernel launch: ceil(numOptions/256) blocks × 256 threads per block
   - Handles automatic host-device memory management with fallback
   - GPU default mode (--cpu flag switches to CPU-only)
   - Automatic fallback to CPU if GPU computation fails

================================================================================
EXECUTION MODEL
================================================================================

COMMAND LINE USAGE:
  mpirun -np <num_processes> ./black-scholes/black_scholes [options]

OPTIONS:
  -n <num>     Number of options to price (default: 10000)
  -v           Enable validation against known values
  -r           Print results for external validation
  --cpu        Use CPU-only computation (default: GPU if available)
  -h           Show this help message

EXECUTION PHASES:
  1. MPI initialization on all ranks
  2. Parameter parsing (rank 0 only), broadcast to all ranks
  3. Generate complete option set (all ranks, deterministic)
  4. Partition options by rank (contiguous subsets)
  5. Compute in parallel:
     - GPU mode: CUDA kernels (default)
     - CPU mode: OpenMP parallel for (--cpu flag)
  6. Gather results to rank 0 via MPI_Gatherv
  7. Validate and print results (rank 0 only)
  8. MPI finalization

SCALING CHARACTERISTICS:
  - Linear MPI scaling: 1-N ranks for N-way speedup
  - OpenMP scaling: 1-T threads for T-way speedup per rank
  - GPU scaling: Automatic load balancing across GPU cores
  - Hybrid advantage: Combine all three levels for maximum throughput

================================================================================
KEY IMPLEMENTATION DECISIONS
================================================================================

1. UNCONDITIONAL PARALLELIZATION:
   - Hybrid approach is always enabled (no fallback to serial)
   - GPU mode enabled by default (--cpu switches to CPU mode)
   - All three levels active when available

2. DETERMINISTIC CORRECTNESS:
   - All ranks generate identical option set
   - Each rank processes subset, enabling scalable distribution
   - Results gathered in order to maintain reproducibility

3. AUTOMATIC FALLBACK:
   - GPU computation attempts execution with try-catch
   - Fallback to OpenMP CPU implementation if GPU fails
   - Ensures robustness on heterogeneous systems

4. DYNAMIC SCHEDULING:
   - OpenMP uses schedule(dynamic) for load balancing
   - Handles uneven work distribution naturally

5. MINIMAL COMMUNICATION OVERHEAD:
   - Single MPI_Bcast for parameters (O(log P))
   - Single MPI_Gatherv for results (O(log P))
   - Work distribution is local (no communication)
