The `roomsim` benchmark has been parallelized using CUDA for GPU acceleration. The changes were made entirely within the existing `roomsim/roomsim.cpp` and `roomsim/CMakeLists.txt` files, preserving the original semantics and ensuring correct execution.

### Key Changes:

1.  **CUDA Integration**:
    *   Updated `CMakeLists.txt` to enable CUDA language support (`LANGUAGES CXX CUDA`) and link against the CUDA Toolkit.
    *   Marked `roomsim.cpp` to be compiled as CUDA code.

2.  **Data Structure Adaptation**:
    *   Added `LinearOctreeNode` structure to flatten the recursive pointer-based `Octree` into a linear array suitable for GPU traversal.
    *   Implemented `Octree::flatten` to convert the host octree into this linear format.
    *   Updated `SimulationState` to manage GPU memory pointers for triangles, octree nodes, and simulation data (form factors, radiosity, etc.).

3.  **Kernel Implementation**:
    *   **`computeFormFactorsKernel`**: Replaces the CPU-based Monte Carlo form factor computation. It uses the flattened linear octree for accelerated ray blocking checks on the GPU.
    *   **`computeTimeDelaysKernel`**: Parallelizes the O(N^2) time delay calculation.
    *   **`simulationStepKernel`**: Parallelizes the wave propagation step for each timestep.
    *   **`computeDistancesKernel`**: Parallelizes the cross-correlation step for distance estimation.

4.  **Host Code Modification**:
    *   Updated `computeFormFactors`, `computeTimeDelays`, `runSimulation`, and `computeDistances` functions to allocate GPU memory, transfer data, launch kernels, and retrieve results.
    *   Added `__host__ __device__` qualifiers to `Vec3` and `Triangle` methods to allow code sharing.
    *   Disabled the original sequential CPU implementations of the heavy computational functions using preprocessor directives (`#if 0`).

The resulting program unconditionally uses the GPU for all major computational phases, providing significant speedups for large triangle counts while passing the built-in validation checks.
