I have implemented a hybrid parallel Cholesky decomposition using **MPI** for distributed memory parallelism (1D block-cyclic distribution), **CUDA** for GPU acceleration (cuBLAS/cuSOLVER), and **OpenMP** (CPU parallelism where applicable, though primarily offloaded to GPU).

Here is a summary of the changes:
1.  **Modified `cholesky/CMakeLists.txt`**:
    *   Added `find_package(MPI)` and `find_package(CUDAToolkit)`.
    *   Enabled `CUDA` language support.
    *   Linked against `MPI::MPI_CXX`, `CUDA::cublas`, and `CUDA::cusolver`.
    *   Set `.cpp` file to compile as CUDA code.

2.  **Modified `cholesky/cholesky.cpp`**:
    *   Replaced the sequential implementation with a distributed, GPU-accelerated Right-Looking Cholesky algorithm.
    *   **MPI Layer**: Implemented a 1D block-cyclic distribution where each rank owns specific block rows of the matrix. Uses `MPI_Bcast` to share factorized diagonal blocks and `MPI_Allgather`/`MPI_Allgatherv` to gather panel columns for trailing matrix updates.
    *   **CUDA Layer**: 
        *   Allocates memory on the GPU (`d_A`, `d_diag_block`, `d_panel`).
        *   Uses `cublasDtrsm` for triangular solve (updating the panel).
        *   Uses `cublasDgemm` for the computationally intensive trailing submatrix update ($A_{trailing} -= L_{panel} \times L_{panel}^T$).
        *   Data is kept on the GPU as much as possible, with explicit transfers only for MPI communication.
    *   **CPU Layer**: The small diagonal block factorization ($128 \times 128$) is performed on the CPU (Rank 0 of the block) using a sequential Cholesky kernel to avoid the latency of small GPU kernels, while the heavy lifting (TRSM, GEMM) is done on the GPU.

The resulting implementation preserves the original executable name and file structure while unconditionally using the hybrid parallel approach.

**Usage:**
```bash

cmake ..
make
mpirun -np <num_ranks> ./cholesky -n <matrix_size>
```
