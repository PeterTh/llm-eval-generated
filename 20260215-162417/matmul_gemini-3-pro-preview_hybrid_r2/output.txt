The `matmul` benchmark has been parallelized using a hybrid approach combining MPI, OpenMP, and CUDA as requested.

### Changes Made

1.  **Modified `matmul/matmul.cpp`**:
    *   **MPI**: Implemented distributed memory parallelism. Rank 0 initializes the matrices and scatters matrix `A` (row-wise) to all ranks. Matrix `B` is broadcast to all ranks. After computation, results are gathered back to Rank 0.
    *   **CUDA**: Implemented a CUDA kernel `matrixMulKernel` for the matrix multiplication. Each MPI rank allocates GPU memory, copies its local chunk of `A` and the full `B` to the GPU, executes the kernel, and copies the result back to host memory. Multi-GPU nodes are supported by assigning devices based on local rank (logic included to split communicator).
    *   **OpenMP**: Used for parallel initialization of matrices and validation of results on the host (Rank 0), ensuring that even non-GPU parts of the workload utilize available CPU cores.

2.  **Updated `matmul/CMakeLists.txt`**:
    *   Added `CUDA` to the project languages.
    *   Added dependency checks for `MPI`, `OpenMP`, and `CUDAToolkit`.
    *   Configured `matmul.cpp` to be treated as a CUDA source file.
    *   Linked against MPI, OpenMP, and CUDA libraries.

### Parallelization Strategy
*   **Inter-node**: MPI distributes the rows of matrix `A`.
*   **Intra-node (Compute)**: CUDA offloads the heavy matrix multiplication `C_local = A_local * B` to the GPU.
*   **Intra-node (Host)**: OpenMP parallelizes data generation and validation loops.

The executable name remains `matmul`, and no new files were created. The program now unconditionally uses this hybrid parallel configuration.
