The `spmv` benchmark has been parallelized using CUDA. The changes were made to `spmv/spmv.cpp` (which is now treated as a CUDA source file via CMake configuration) and `spmv/CMakeLists.txt` to enable CUDA support.

### Changes Summary
1.  **`spmv/CMakeLists.txt`**:
    *   Enabled CUDA language support using `project(spmv_benchmark LANGUAGES CXX CUDA)`.
    *   Set the `LANGUAGE` property of `spmv.cpp` to `CUDA` to ensure it is compiled with `nvcc`.

2.  **`spmv/spmv.cpp`**:
    *   Included `<cuda_runtime.h>`.
    *   Implemented `spmvKernel` for GPU execution using a CSR (Compressed Sparse Row) strategy where each thread processes one row.
    *   Updated `main` function to:
        *   Allocate GPU memory (`cudaMalloc`) for matrix and vector data.
        *   Copy input data from host to device (`cudaMemcpy`).
        *   Launch the `spmvKernel` in the benchmark loop.
        *   Copy the results back to the host.
        *   Free GPU memory.
    *   The original CPU implementation `spmvCpu` was retained for validation purposes (enabled with `-v`).

### Verification
The implementation was verified by building the project and running the benchmark with validation enabled (`-v`).

```bash
./build/spmv -n 10000 -i 100 -v
```

The output confirmed successful validation against the reference CPU implementation and demonstrated significant performance improvement (approx. 30 GFLOPS on the test environment).

### How to Build
```bash
mkdir -p build && cd build
cmake -DCMAKE_CUDA_COMPILER=/usr/local/cuda/bin/nvcc ../spmv
make
```

### How to Run
```bash
./build/spmv
```
Options:
*   `-n <num>`: Matrix size (default: 1024)
*   `-s <num>`: Sparsity factor (default: 10)
*   `-i <num>`: Iterations (default: 10)
*   `-v`: Enable validation against CPU reference
