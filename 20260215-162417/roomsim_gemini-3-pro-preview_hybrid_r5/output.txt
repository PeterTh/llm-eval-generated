The `roomsim` benchmark has been parallelized using a hybrid MPI + OpenMP + CUDA approach for accelerator clusters.

### Parallelization Strategy
1.  **MPI (Distributed Memory):**
    *   The simulation domain (triangles) is decomposed across MPI ranks. Each rank is responsible for computing a subset of rows in the $K_{ij}$ (form factor) and $\tau$ (time delay) matrices.
    *   `computeFormFactors` and `computeTimeDelays` perform local computations without communication.
    *   `runSimulation` synchronizes the radiosity vector `radB` across all ranks after each timestep using `MPI_Allgatherv`, ensuring all ranks have the full history required for propagation.
    *   `computeDistances` computes local results and gathers the full distance array using `MPI_Allgatherv`.
    *   Validation uses `MPI_Reduce` to aggregate distributed results (e.g., non-zero form factor counts).

2.  **OpenMP (Shared Memory):**
    *   Used to parallelize loops within each MPI rank for `computeFormFactors` and `computeTimeDelays`, accelerating the CPU-intensive ray tracing and geometry calculations.

3.  **CUDA (GPU Acceleration):**
    *   The core wave propagation loop in `runSimulation` is offloaded to the GPU.
    *   A CUDA kernel `simulation_kernel` computes the radiosity update for the local subset of triangles.
    *   Data transfer is optimized: the large, static matrices ($K_{ij}$, $\tau$) are copied to the GPU once at the start of the simulation. Only the time-varying radiosity data is transferred between host and device at each timestep.

### Build Instructions
The `CMakeLists.txt` has been updated to support these technologies. To build:
```bash
cd roomsim
mkdir build && cd build
cmake ..
make
```

### Execution
Run with `mpirun` specifying the number of processes (ranks):
```bash
mpirun -n <num_ranks> ./roomsim [options]
```
Example:
```bash
mpirun -n 4 ./roomsim -v
```
