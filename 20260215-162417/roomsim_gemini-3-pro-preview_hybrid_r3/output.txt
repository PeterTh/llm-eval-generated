The `roomsim` benchmark has been parallelized using a hybrid approach combining MPI, OpenMP, and CUDA to maximize performance on accelerator clusters.

### Parallelization Strategy
1.  **MPI (Distributed Memory):**
    *   The outer loops over triangles (`i`) in all major compute functions (`computeFormFactors`, `computeTimeDelays`, `runSimulation`, `computeDistances`) are distributed across MPI ranks.
    *   Each rank is responsible for computing a subset of the result rows (e.g., a slice of the form factor matrix or radiosity array).
    *   `MPI_Allgatherv` is used in `runSimulation` to synchronize the radiosity vector (`radB`) at each timestep, ensuring all ranks have the necessary data for the next step.
    *   `MPI_Allgatherv` is used in `computeDistances` to gather the final results for validation and output.

2.  **OpenMP (Shared Memory):**
    *   Within each MPI rank, OpenMP is used to parallelize the inner loops on the CPU.
    *   `#pragma omp parallel for` is applied to the `i` loop in `computeFormFactors` (with thread-local random number generators) and `computeTimeDelays`.
    *   It also accelerates `runSimulation` and `computeDistances` when CUDA is not available.

3.  **CUDA (GPU Acceleration):**
    *   If the CUDA Toolkit is found, `runSimulation` and `computeDistances` are offloaded to the GPU using CUDA kernels.
    *   These phases involve dense matrix-vector operations and are highly suitable for GPU acceleration.
    *   `computeFormFactors` remains on the CPU (MPI+OpenMP) due to the pointer-heavy octree traversal which is not easily portable to GPU without significant data structure changes.
    *   Data transfer is minimized by copying static data (`kij`, `tau`, `areas`) once and only synchronizing `radB` at each timestep.

### Changes
*   **`roomsim/CMakeLists.txt`**: Added `find_package` for MPI, OpenMP, and CUDAToolkit. Configured the build to link against these libraries and enable CUDA language support if available.
*   **`roomsim/roomsim.cpp`**:
    *   Initialized MPI in `main`.
    *   Added logic to partition the triangle workload among MPI ranks (`localStart`, `localEnd`).
    *   Inserted OpenMP pragmas for CPU parallelism.
    *   Implemented CUDA kernels for `runSimulation` and `computeDistances` inside `#ifdef USE_CUDA` blocks.
    *   Added MPI communication (Allgatherv) to synchronize state between distributed ranks.
    *   Ensured correct validation and output by aggregating results to rank 0.

The resulting program unconditionally uses the best available parallelization method (MPI+OpenMP+CUDA if compiled with CUDA, otherwise MPI+OpenMP).
