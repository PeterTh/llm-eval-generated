## Parallelization Strategy

### MPI (Distributed Memory)
- **Row-wise distribution**: Matrix rows are partitioned across MPI ranks using contiguous blocks
- **Data distribution**: Rank 0 generates the full CSR matrix, then broadcasts `rowDelimiters` and `vec` to all ranks, and sends local `val`/`cols` partitions via point-to-point MPI sends
- **Result gathering**: Local output vectors are gathered on rank 0 using `MPI_Gatherv`
- **Performance measurement**: Uses `MPI_Reduce` with `MPI_MAX` to get wall-clock time across all ranks

### OpenMP (Shared Memory)
- **`fill()`**: Parallelized array initialization with `#pragma omp parallel for`
- **`spmvCpu()`**: Parallel CPU reference computation with `#pragma omp parallel for schedule(static)`
- **`verifyResults()`**: Parallel validation with `#pragma omp parallel for reduction(||:valid)`

### CUDA (GPU Acceleration)
- **SpMV kernel**: Each GPU thread handles one matrix row, computing the dot product of that row with the input vector
- **GPU assignment**: Round-robin mapping of MPI ranks to available GPUs (`rank % numGpus`)
- **Memory management**: Device memory allocated per-rank for local CSR data and the full input vector
- **Timing**: Uses `cudaDeviceSynchronize()` for accurate timing

### Key Design Decisions
- The full `vec` is broadcast to all ranks (read-only, needed for every row)
- Each rank only stores and computes its local row subset
- The CUDA kernel uses 1 thread per row for simplicity and correctness (optimal for sparse matrices where row lengths vary)
- The executable name remains `spmv` and must be run via `mpirun -np <N> ./spmv`
