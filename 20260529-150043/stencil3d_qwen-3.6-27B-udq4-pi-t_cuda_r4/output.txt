The stencil3d benchmark has been successfully parallelized with CUDA. Here's a summary of the changes:

## Changes Made

### `stencil3d/CMakeLists.txt`
- Added `CUDA` language to the `project()` declaration
- Added `set_source_files_properties(stencil3d.cpp PROPERTIES LANGUAGE CUDA)` to compile the `.cpp` file with nvcc (preserving the original file extension)

### `stencil3d/stencil3d.cpp`
**Three CUDA kernels:**

1. **`stencilKernel`** - Main 7-point stencil with shared memory tiling:
   - 3D thread blocks (32×8×4 = 1024 threads) matching the shared memory tile
   - Shared memory tile with 1-cell halo on each face (`sTile[34][10][6]`) for coalesced global memory access
   - Each thread loads one element from global to shared memory, then computes stencil using only shared memory reads
   - Handles both interior stencil computation and boundary value copying in a single kernel

2. **`initKernel`** - Grid initialization on GPU using grid-stride loop

3. **`validateKernel`** - NaN/Inf check on GPU using grid-stride loop

**Host-side changes:**
- GPU device detection and property reporting
- Device memory allocation with double buffering (`d_grid1`, `d_grid2`)
- All stencil iterations run entirely on GPU (data never transferred during computation)
- Single device-to-host copy of final result for validation/printing
- CUDA error checking macro throughout

All validation tests pass across cubic and non-cubic grids, with both even and odd iteration counts.
