## Summary

### Parallelization Strategy

**MPI (Domain Decomposition)**
- Z-dimension decomposition across MPI ranks
- Each rank owns a contiguous block of Z-slices plus 1-cell halo regions on internal faces
- Non-blocking halo exchange using `MPI_Isend`/`MPI_Irecv` between neighboring ranks

**CUDA (GPU Acceleration)**
- Unified kernel: computes 7-point stencil on interior points, copies boundaries/halos for non-interior points
- 3D thread block configuration (16×16×4) for coalesced memory access
- Double-buffered device memory to avoid read-after-write hazards
- Grid initialization on GPU

**OpenMP**
- Included and linked for CPU-side parallel operations (available for halo exchange overlap)

### Key Design Decisions

1. **Domain decomposition along Z**: Best for GPUs since each rank processes full XY planes
2. **Unified kernel**: Single kernel handles both stencil computation and boundary copy, avoiding synchronization issues
3. **Local indexing**: All CUDA kernels use local indices relative to each rank's subdomain
4. **Correct boundary handling**: Interior excludes both halo regions AND global Z boundaries (z==0, z==nz-1)
