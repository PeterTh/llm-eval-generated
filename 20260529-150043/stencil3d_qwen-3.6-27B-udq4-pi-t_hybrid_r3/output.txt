The stencil3d benchmark has been parallelized with a hybrid MPI + OpenMP + CUDA approach. Here's a summary:

## Parallelization Strategy

### MPI (Domain Decomposition)
- **Z-axis decomposition**: The 3D grid is split along the Z dimension across MPI ranks
- **Halo exchange**: 1-layer halo regions are exchanged between neighboring ranks using non-blocking `MPI_Isend`/`MPI_Irecv`
- Handles uneven grid sizes (remainder distributed to lower-ranked processes)
- Results gathered on rank 0 for validation/output

### CUDA (GPU Acceleration)
- **7-point stencil kernel**: Each thread computes one interior grid point on the GPU
- **Block size**: 8×8×4 threads for coalesced memory access patterns
- **Persistent allocations**: Device memory allocated once and reused across iterations
- **CUDA streams**: Async memory transfers (`cudaMemcpyAsync`) with stream synchronization
- One GPU per MPI rank (round-robin assignment)

### OpenMP (CPU-side parallelism)
- **Initialization**: Parallel grid initialization with `collapse(3)`
- **Boundary copy**: Parallel boundary value copying with `collapse(3)`
- **Halo packing/unpacking**: Parallel halo data preparation with `collapse(2)`

## Performance Results
| Configuration | Performance |
|---|---|
| 1 rank, 128³ | ~390 MCellUpdates/s |
| 3 ranks, 128³ | ~677 MCellUpdates/s (1.7x speedup) |
| 4 ranks, 256³ | ~682 MCellUpdates/s |
| 4 ranks, 512³ | ~1065 MCellUpdates/s |

## Key Design Decisions
- Global index-based initialization ensures identical initial values across all MPI configurations
- Double buffering (grid1/grid2) for ping-pong stencil iterations
- Validation and result gathering on rank 0 for correctness verification
- All sample values match between single-rank and multi-rank runs
